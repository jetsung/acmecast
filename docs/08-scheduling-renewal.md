# 8. 调度与自动续期

调度是**自动触发**的来源（此外还可通过 `POST /api/pipelines/{id}/run` 手动触发一次，
见 [06-pipelines-and-tasks.md](06-pipelines-and-tasks.md) 6.7）。一条流水线最多挂一份调度，
配置两种触发方式（可同时启用）：

- **cron 表达式**：到点自动执行；
- **续期域名集合**：周期扫描证书仓库，剩余有效期不足阈值时自动触发。

## 8.1 调度端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/schedules` | 全部调度配置 |
| POST | `/api/schedules` | 新建或更新（按 `pipeline_id` 覆盖，即 upsert） |

请求体：

```json
{
  "pipeline_id": 1,
  "cron": "0 3 * * *",
  "enabled": true,
  "catch_up": false,
  "renewal_domains": ["example.com", "www.example.com"]
}
```

| 字段 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `pipeline_id` | 是 | — | 所属流水线，唯一 |
| `cron` | 否 | `null` | cron 表达式；`null` 或空表示不按 cron 触发（仍可参与续期扫描） |
| `enabled` | 否 | `true` | 停用后不再有任何自动触发 |
| `catch_up` | 否 | `false` | 停机补跑策略（见 8.3） |
| `renewal_domains` | 否 | `null` | 该流水线负责续期的域名集合；空表示不参与续期触发 |

响应含运行态缓存字段：`last_triggered_at`、`next_trigger_at`。

## 8.2 cron 表达式

- 支持 **5 段**（`分 时 日 月 周`，如 `0 3 * * *`）与 **6/7 段**
  （`秒 分 时 日 月 周 [年]`）；
- 5 段输入会被规范化为「整分零秒」（前面补 `0 0`）；
- 表达式在**保存时校验**，非法表达式返回 400 `validation_error`；
- **按 UTC 计算**。例如 `0 3 * * *` 触发于 03:00 UTC（北京时间 11:00）。
  前端预览使用东八区显示，实际触发以服务端 UTC 为准，请以 UTC 换算填写。

常见示例：

| 表达式 | 含义（UTC） |
| --- | --- |
| `* * * * *` | 每分钟（调试用） |
| `0 3 * * *` | 每天 03:00 |
| `0 3 * * 1` | 每周一 03:00 |
| `0 0 3 1 * *` | 每月 1 日 03:00（6 段：秒 分 时 日 月 周） |

## 8.3 停机补跑（`catch_up`）

服务启动时会为所有启用且有 cron 的调度重算 `next_trigger_at`，并处理
「上次停机期间错过的触发点」：

- `catch_up = true`：**补跑最近一次**错过的触发点（且仅此一次，更早的作废），
  审计里记为 `cron` 且带「停机补跑」说明；
- `catch_up = false`（默认）：直接跳过错过的点，等待下一次正常触发。

## 8.4 到期扫描与续期

- 扫描周期：**1 小时**（与 cron 检查周期 30 秒解耦，扫描按周期节流）；
- 续期阈值：证书**剩余有效期 ≤ 30 天**进入续期窗口；
- **已吊销证书自动排除**；
- 匹配规则：证书覆盖的**任一域名**出现在某条启用调度的 `renewal_domains` 中即命中；
  按顺序取**第一条**匹配的调度，同一张证书一次扫描只产生一次触发；
- 若证书进入续期窗口但没有调度声明负责它的域名，只记一条 warn，不触发。

续期触发会写审计记录（说明「证书 X 距到期不足 N 天」）。触发时：

- 同一去重窗口（1 小时）内不重复触发同一条流水线的续期；
- 流水线正在运行时跳过本次触发。

## 8.5 去重与并发

| 触发来源 | 去重方式 |
| --- | --- |
| cron | 触发成功后推进 `next_trigger_at`，同一触发点不会被消费两次 |
| renewal | 去重窗口（1 小时）内不重复触发；靠触发审计记录判定 |

**运行中检查**（两种来源都适用）：若目标流水线仍有 `running` 状态的运行历史，
跳过本次触发——并发运行同一流水线会让证书请求、文件写入互相踩踏。

- cron 被运行中检查拦下时：仍推进触发点（视为已消费），避免每轮重复尝试；
- 续期被拦下时：不落审计记录（这不是一次真正的触发），否则会不断刷新去重窗口基准。

## 8.6 触发失败与重试

- **cron 启动失败**（如流水线配置坏了）：**不推进触发点**，下一轮 tick 到点再试；
- **续期启动失败**：落一条「启动失败」的审计记录，并因去重窗口而不会形成触发风暴；
  一张证书的续期问题不会中断整个扫描。

## 8.7 触发审计

每次真正发出启动请求都会落一条触发记录，包含流水线、来源（`cron`/`renewal`）、
说明与时间。**当前没有查询触发审计的 API**，需要直接查数据库中的触发记录表。

## 8.8 触发来源与历史

运行历史的 `trigger_source` 取值：

| 取值 | 含义 |
| --- | --- |
| `cron` | cron 到点或停机补跑触发 |
| `renewal` | 到期扫描触发 |
| `manual` | 通过 `POST /api/pipelines/{id}/run` 手动触发 |

查看运行历史与日志：

```bash
curl -sS -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8080/api/histories?pipeline_id=1&page=1&page_size=20"
curl -sS -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/histories/12/logs
```
